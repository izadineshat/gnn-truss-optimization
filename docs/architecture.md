# معماری پروژه

این سند توضیح میدهد هر بخش کد چه کاری میکند و چرا آنطور چیده شده است.
سند آموزشی گامبهگام (به فارسی) در [`../amozeshi/roadmap.md`](../amozeshi/roadmap.md) است.

## نگاه کلی

```
        ورودی (هندسه + مقطع + بار)
                  │
                  ▼
     ┌────────────────────────┐
     │  trussgnn.fem          │  تحلیل اجزای محدود (کند ولی دقیق)
     │  TrussModel            │
     │  assemble_global_...   │
     │  solve_truss           │
     └───────────┬────────────┘
                 │  جابجایی، نیرو، تنش  ← «جواب درست» (ground truth)
                 ▼
     ┌────────────────────────┐
     │  trussgnn.graph        │  تبدیل خرپا به گراف
     │  edge_index, A, D, L   │
     └───────────┬────────────┘
                 │  دادهی آموزش (ورودی گرافی + برچسب)
                 ▼
     ┌────────────────────────┐
     │  trussgnn.models       │  GNN: پیامگذاری روی گراف  (گام ۷)
     └───────────┬────────────┘
                 │  جانشین سریع (surrogate)
                 ▼
     ┌────────────────────────┐
     │  trussgnn.optimize     │  کمینهسازی وزن با محدودیت تنش (گام ۸)
     └────────────────────────┘
```

## ماژولها

### `trussgnn.fem` — هستهی اجزای محدود

| موجودیت | نقش |
|---|---|
| `TrussModel` | تعریف مسئله: گرهها، اعضا، `E`، `A`، درجات آزادی مقید. تغییرناپذیر (frozen dataclass) و خوداعتبارسنج. |
| `element_stiffness` | ماتریس سختی ۴×۴ یک عضو: `k = (E·A/L)·λ⊗λ`. |
| `assemble_global_stiffness` | اسمبل ماتریس سختی کل با همان حلقهی دوتایی کد آموزشی. |
| `solve_truss` | حل یک حالت بار: جابجایی → عکسالعمل → نیروی داخلی → تنش → چک تعادل. |
| `TrussResult` | خروجی کامل تحلیل، شامل `equilibrium_error` برای اعتبارسنجی. |
| `canonical_triangle` / `solve_tutorial` | همان مسئلهی `truss_analysis.py` بهصورت نامدار، تا تست و کد آموزشی همگام بمانند. |

**قرارداد علامت:** `N > 0` یعنی کشش، `N < 0` یعنی فشار. تنش `σ = N/A`.

### `trussgnn.graph` — خرپا بهشکل گراف

| موجودیت | نقش |
|---|---|
| `edge_index` | فهرست یال دوجهته به سبک PyTorch Geometric (۲ ردیف). |
| `adjacency_matrix` | `A[i][j] = 1` اگر عضو `(i,j)` وجود داشته باشد. |
| `degree_matrix` / `laplacian_matrix` | `D` و `L = D - A`. |
| `normalized_laplacian` | `L_sym = I - D^{-1/2} A D^{-1/2}` با محافظت از گرههای منزوی. |
| `edge_attributes` | ویژگی یال (سطح مقطع)، دو بار برای هر عضو (رفت و برگشت). |
| `truss_to_graph` | ساخت یکجای همهی موارد بالا. |

### `trussgnn.plot` — رسم

`matplotlib` بهصورت تنبل (lazy) درون توابع ایمپورت میشود تا هستهی FEM سبک بماند.
`plot_member_stress` رنگ عضو را بر اساس علامت تنش (کشش/فشار) انتخاب میکند.

### ماژولهای آینده

`data/`، `models/` و `optimize/` فعلاً جاینگهدار (placeholder) هستند و در گامهای
۵، ۷ و ۸ پر میشوند. هیچکدام وابستگی سنگین (PyTorch) را در نصب پایه اضافه نمیکنند؛
با `uv sync --extra ml` فعال میشوند.

## تصمیمهای طراحی

1. **src-layout.** کد در `src/trussgnn/` است تا تستها همان چیزی را ایمپورت کنند که
   کاربر نصب میکند، نه یک پوشهی محلی تصادفی.
2. **جدا نگه داشتن تمرینهای آموزشی از کد پکیج.** `week1/`, `single_bar_exercise/` و
   `amozeshi/` دستنخورده میمانند؛ پکیج، نسخهی مهندسیشدهی همان مفاهیم است.
3. **اعتبارسنجی درونکد.** `TrussResult.equilibrium_error` هر تحلیل را خودش چک میکند؛
   یک خرپای ناپایدار خطای واضح میدهد، نه جواب بیمعنی.
4. **تست مبتنی بر محاسبهی دستی.** هر رابطهی فیزیکی یک تست دارد
   (مثلاً دو عضو متقارن باید نیروی برابر داشته باشند).
5. **وابستگیهای سبک در نصب پایه.** فقط `numpy`، `matplotlib` و `scipy`؛
   PyTorch در extras قرار دارد.
